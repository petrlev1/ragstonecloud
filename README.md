# Облако

Личный веб-сервис файлов (аналог Google Drive) на FastAPI.
Отдаёт домашний каталог сервера через браузер.

## Запуск

    ./run.sh            # первый раз спросит пароль и создаст config.json
                        # (или: CLOUD_PASSWORD=... ./run.sh — без вопросов)

Сервис: http://<хост>:8080  (порт/хост: PORT=..., HOST=...)

## Вход: логин и пароль

Вход — логин + пароль. Логин (ключ `user` в config.json, регистр не важен) и
PBKDF2-хеш пароля лежат в config.json — вне git:

    ./venv/bin/python app/setup.py --user 'имя_пользователя' --password 'новый_пароль'

Без `--user`/`--password` setup.py спросит оба: логин — с текущим значением в
подсказке, пароль — Enter, чтобы оставить прежний.
Нет ключа `user` в config.json — вход по одному паролю (совместимость со старыми конфигами).

## Устройство

- `app/` — FastAPI-приложение (main.py — маршруты, auth.py — логин/пароль и сессии,
  storage.py — безопасный доступ к файлам, deleter.py — удаление в фоне с прогрессом,
  indexer.py — поиск по содержимому, shares.py — общие ссылки, disks.py — диски и место,
  preview.py — миниатюры и тексты для просмотра, config.py — конфиг, setup.py — создание конфига)
- `static/index.html` — интерфейс (один файл, без сборки)
- `static/gallery.js`, `static/gallery.css` — галерея и окно просмотра файлов (общие для
  интерфейса владельца и гостевой страницы ссылки)
- `config.json` — корень хранилища, секрет сессий, логин и хеш пароля, доступ к БД индекса. Вне git!
- Полнотекстовый поиск — PostgreSQL (БД `cloud`): русская морфология + pg_trgm по именам
- Первичная индексация: ~61 тыс. файлов ≈ 8-10 минут в фоне (лог: /tmp/cloud.log)

## Галерея и просмотр файлов

Кнопка «⬚ Галерея / ☰ Список» в шапке переключает вид содержимого папки (выбор запоминается
в браузере). Клик по файлу открывает окно просмотра: скачивание, общая ссылка (у владельца),
перелистывание стрелками ←/→ по всем файлам папки, Esc — закрыть. Просматриваются картинки,
PDF, видео, аудио и тексты/код; для остальных типов — «предпросмотр недоступен» и кнопка скачать.

Миниатюры картинок готовит Pillow и складывает в дисковый кэш (по умолчанию `.thumbcache/`
в каталоге проекта, ключ `thumb_cache` в config.json). Pillow в requirements.txt; без него
сервис работает, но галерея грузит полные картинки:

    POST /api/thumb?path=...&w=240   -> jpeg из кэша (или 415, если миниатюра недоступна)
    POST /api/text?path=...          -> {"text", "truncated", "encoding", "size"} (utf-8, затем cp1251)

Те же ручки для гостя: `/api/s/<token>/thumb`, `/api/s/<token>/text`.
Тесты: `./venv/bin/python test_gallery.py` (данные — `make_test_media.py`).

## Удаление: прогресс и отмена

Большое дерево удаляется минутами, поэтому удаление идёт в фоне, а внизу страницы
видна строка состояния: сколько всего предстоит удалить (файлы/папки/МБ), сколько уже
удалено, скорость и оценка остатка — с кнопкой «Отменить».

    POST /api/delete          {"path": "..."}  -> {"ok": true, "job": {...}}
    GET  /api/delete/status                    -> {"active": bool, "job": {...}}
    POST /api/delete/cancel                    -> {"ok": true, "cancelled": bool}

Отмена необратима: недоудалённая часть дерева остаётся на диске как есть.
Пока идёт одно удаление, второе отклоняется (409). Тесты: `./venv/bin/python test_delete.py`.

## Безопасность

- Пароль хранится только как PBKDF2-хеш, секрет сессий — в config.json (права 600)
- Вход ограничен по скорости (5 попыток/мин с IP)
- Всё ходит строго внутри корня хранилища (проверка реальных путей)
- Сейчас это HTTP — при публичном доступе из интернета завернуть в HTTPS (Caddy)
